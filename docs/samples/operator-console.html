開示されたギャップ（この実行で観測したもの、直していない）

Building this page was the first time this repo's actor had ever been driven outside its test suite. These are defects observed by running it. They are disclosed rather than silently patched, because quietly fixing a governor inside a rendering task hides the finding.

  1. run-operation cannot distinguish a refusal from an escalation in the ledger. Its single :ok? gate sends both through hold-fact, so both are :t :governor-hold. Measured on this run: 30 such facts, of which 23 are refusals and 7 are escalations with an empty :basis. A consumer counting fact types overstates refusals by 7.
  2. An approved operation writes no audit fact at all. run-operation returns {:ok? true :facts []} — the commit path yields an empty fact vector, so an append-only ledger fed only by the actor records every refusal and no success. The driver-marked facts above exist only because this renderer adds them.
  3. Soft violations never reach the ledger. hold-fact copies :violations but not :soft-violations, so the 3 soft rules in the table above are invisible to any ledger reader — the escalation they caused is indistinguishable from one caused by high stakes alone.
  4. The store has no approver slot. log-batch / finalize-shipment take no approver parameter, so the human who signed off cannot survive onto the batch register. Probed at render time rather than asserted — see the approval trail above.
  5. mealops.sim is a stub that prints “not yet implemented”, and mealops.advisor is a docstring with no proposal function in it, so the proposal shape is supplied by this renderer's driver. The :dev alias's :override-deps for langgraph/langchain is inert — neither library is in :deps, and mealops.operation is a plain function, not a compiled StateGraph, so nothing here calls langgraph.graph/run*.
